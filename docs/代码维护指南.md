# 代码维护指南

## 建议阅读顺序

1. 根目录 `README.md`：整个系统的组成、启动和部署。
2. `frontend/README.md`：从页面定位 React 入口和具体组件。
3. `src/main/java/com/qpwflshclub/formal_club/` 中对应的控制器：请求路径、会话和权限检查。
4. 控制器依赖的服务、Repository 或 Store：业务处理及持久化。
5. 对应的 `src/test/` 或 `frontend/tests/`：修改前先看预期行为。

本项目使用 React、Spring Boot、Thymeleaf、JPA，以及独立运行的 MRBS / PHP 预约系统。大部分业务与交互自行编写，并不意味着没有框架。提升可读性不需要更换这些技术。

## 后端模块地图

Java 包根目录是 `src/main/java/com/qpwflshclub/formal_club/`。

| 包 / 文件 | 负责什么 |
| --- | --- |
| `controller/`、`service/` | 原有页面、账号、社团及建议接口与业务逻辑 |
| `pojo/`、`repository/` | 数据库实体与 JPA 查询，涉及已有学校数据库 |
| `config/` | 登录过滤器、会话、密码、验证码、缓存及服务配置 |
| `social/SocialPageController.java` | 校园墙、私信等页面路由 |
| `social/SocialController.java` | 帖子、评论、互动与私信接口 |
| `social/CommunityController.java` | 当前账号、个人资料、社团身份与消息密钥接口 |
| `social/SchoolAccounts.java` | 跨学生、教师、社长、管理员表解析账号和展示身份 |
| `social/SocialStore.java` | 帖子和消息等私有 JSON 持久化 |
| `social/MessageRecovery.java` | 与登录密码独立的服务器加密密钥恢复 |
| `social/NotificationController.java`、`SocialNotifications.java` | 通知读取、未读和持久化 |
| `social/PasswordRecoveryController.java` | 邮箱验证码及密码找回 |
| `social/AccountDeletionController.java` | 账号注销与关联数据清理 |
| `social/PersonalWelcomeStore.java` | 账号专属欢迎内容与一次性展示记录 |
| `social/LockedBadges.java` | 服务器分配的固定徽章，独立于用户可编辑标签 |
| `workspace/WorkspaceAccess.java` | 工作台会话、写入令牌及社团权限边界 |
| `workspace/WorkspaceController.java`、`WorkspaceStore.java` | 工作台资料、附件和活动 |
| `workspace/ClubOperationsController.java`、`ClubOperationsStore.java` | 学期、考勤、报告和招募 |

Controller 接收 HTTP 请求；Service / Store 处理业务与数据。不是所有实体都在 MySQL：部分新功能使用私有 JSON 文件。查找实际存储位置时搜索对应类的 `@Value`，不要根据文件名猜测数据库表。

## 一条请求如何流动

以校园墙为例：页面控制器返回 `templates/page/campus-social.html` → 模板挂载 `frontend/social.jsx` → `SocialPost.jsx` 展示帖子并发送请求 → `/api/campus-social` 控制器检查当前会话和写入令牌 → 服务更新私有数据 → 前端刷新结果。

`X-Workspace-Token` 来自已验证会话，用于写入请求。公开显示的账号 ID、头像或角色不是登录凭据。账号身份由服务端解析，不能通过前端参数选择要冒充的账号。

密码找回后的聊天恢复依赖服务器加密保存的原始密钥，不依赖新登录密码生成替代密钥。没有任何可用备份的历史密钥无法补回。用户欢迎图片、欢迎标记、账号徽章分配、聊天记录和登录凭据都属于运行数据，不能作为源码示例提交。

## 空文件核查

| 文件 | 原因与处理 |
| --- | --- |
| `booking/web/upgrade/<版本>/pgsql.sql` 中的空文件 | 上游 MRBS 的无 SQL 操作迁移。`booking/web/upgrade.inc` 按版本直接 `fopen` 文件，空内容会跳过查询，但版本推进和可选 `post.inc` 仍执行。保持空文件，不随意删除或填入 SQL 注释：该加载器会尝试执行非空内容。 |
| `booking/web/jquery/datatables/DataTables-1.13.6/css/dataTables.dataTables{,.min}.css` | 随上游保留的空样式文件，没有 CSS 规则；不是学校页面缺少实现。保留第三方文件结构。 |
| `src/main/resources/static/javascript/ui/chunks/chunk-5AFER4MZ.js` | 原有空构建模块，部分历史 bundle 仍引用；补充产物说明后保留，避免旧模块导入失败。新构建文件统一带来源说明。 |

Java 的空 record、默认构造器、接口方法和 `contextLoads()` 也不代表功能缺失。`contextLoads()` 的检查发生在 Spring 启动应用上下文时，不应为了填满方法而加入无意义逻辑。

## 格式和文件边界

- `.editorconfig`：编辑器的缩进、编码、换行约定。
- `.prettierrc.json`：Prettier 与 Java 插件的固定格式，JS/JSX/CSS 为 2 空格，Java 为 4 空格。
- `npm run format` / `npm run format:check`：覆盖前端源文件、Java 和 Thymeleaf 模板。HTML 按块级 / 行内元素的空白规则排版，不重排内嵌脚本。
- `.prettierignore`：排除生成文件、第三方源码和运行数据。
- `.gitattributes`：GitHub 将构建结果标为 generated、MRBS 标为 vendored，评审时更容易看到自有源码。

不重新排序 CSS，不更换 DOM 类名和接口参数，不为缩短大文件而同时改业务行为。组件提取优先选择具有独立输入输出的边界；目前将构建中的模板预加载维护提取到 `frontend/build/preloads.mjs`。

## 验证修改

```sh
npm run format:check
npm run test:frontend
npm run build
./mvnw '-Dtest=*Test,!FormalClubApplicationTests' test
./mvnw -DskipTests package
```

`FormalClubApplicationTests` 是需要完整外部服务配置的上下文启动检查，配置好测试数据库等依赖后再单独运行。`EmailTest.main` 是手动 SMTP 排查工具，使用环境变量读取凭据和收件人，自动测试不会执行它；不要用生产邮件发送来验证格式改动。

浏览器检查方式见 `tests/e2e/README.md`。涉及模板、布局和动画的修改还需检查桌面与移动端。纯源码整理不自动发布生产，不改数据库，也不触发真实消息或预约。

### 已知的旧版测试

`ProfileTemplateTest` 的三条断言仍要求 `profile.html` 内存在旧版密码变量、社长路径变量和账号删除脚本。当前模板已改为挂载 `frontend/account.jsx`，注销由 `AccountDeletion.jsx` 调用会话校验接口；这三条断言在此次格式整理前同样失败。后续迁移这些测试时应覆盖当前页面的真实行为，不要为了通过测试恢复旧版脚本。
